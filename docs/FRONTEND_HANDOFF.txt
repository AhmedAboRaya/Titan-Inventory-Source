TITAN INVENTORY frontend candidate — 2026-10-18

Implemented interface
  Arabic RTL and English LTR, light/dark, compact footer and responsive layout.
  Independent login, first-admin setup token form, account/session view, web
  passkeys, native biometric actions, two-minute return lock, explicit logout.
  Warehouse-filtered category -> subcategory -> item cards, search and pagination.
  Item definition, position balances, unit conversions, lots, serials, item levels,
  alternate codes, authorized cost data, image gallery and attachments. Images can
  be photographed/selected, rotated, center-cropped and compressed before upload.
  Warehouses, locations, sites/departments/employees/machines/suppliers, categories,
  users, roles and scopes have forms and read-only details before editing.
  Receipt/issue and supported stock document forms, multi-line drafts, details,
  submit/independent approval/post/cancel/reject/reversal with server versions.
  Purchase orders -> linked receipt draft; counts/physical recount; structured
  item-import preview and independent selected-row approval; period closing.
  Balances/ledger/custody reports with 200-row pages, server Excel export, web
  print/PDF and native print action. No quantities of different units are summed.

Data behavior
  Every submitted business write is stored durably with a UUID before network.
  The same pending path/body reuses the same UUID after an uncertain response.
  Only document Draft save requests retry automatically. Posting, approving,
  reversing and other business actions require explicit user retry in Saved
  locally. Server acknowledgement is required before official success is shown.
  Unsaved document editor state is persisted separately and restored only after
  the user chooses Restore; opening a new editor does not overwrite an older
  local draft before that choice.
  Web IndexedDB keys include instance, account, role version, permissions and
  warehouse/department scopes. Native storage uses the bridge's exact nativeScope
  and encrypted atomic cache. Protected native requests carry accountId+scope so
  an old callback cannot send under another account. No central/shared login.
  Refresh every five seconds is single-flight with backoff; forms retain edits.
  Cached reads show their timestamp and explicitly state that stock is not current.
  Session/cost permissions are rechecked on the server. Cost controls are hidden
  without cost.read. Scope changes replace the visible workspace.
  The service worker caches only an exact static-shell allowlist, never v1 APIs,
  cookies, attachments or business response data. Native uses bundled assets and
  does not register a browser service worker.

First setup
  On initialized=false, the UI requests username/display_name/password/setup_token.
  The token is manually supplied by the server administrator. No token/password
  is put in local/session/IndexedDB or application configuration. Successful setup
  clears the form and returns to ordinary login. Only synthetic tokens/accounts
  were used in the isolated QA fixture.
